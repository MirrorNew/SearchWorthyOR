# SearchWorthyOR-Rapid-v0 生成方法

Rapid-v0 是与严格正式版分离的快速生产轨道。它从 303 条已有来源候选中重新筛选，先形成 100 条主候选和 30 条备用候选，再按 5 批、每批 20 题逐题闭环生成。

每题依次完成：当前官方网页访问、支持段落定位、日期/辖区/主体适用性判断、不同 base 模型构造、规则到结构补丁的绑定、COPT 求解、完整最优行动集合比较、题面与 base 对齐、自检和一名非生成者独立复核。每个批次的复核者由数据合同预先指定；该记录用于流程审计，不宣称密码学身份认证。

每生成 5 题就同时运行模型批次门和网页重抓取门。`support_excerpt` 必须是最终 URL 当前 HTML 或官方 PDF 归一化正文中的一段连续、具体原文，长度不超过 5000 个字符；不能用整页或整份 PDF 代替定位，也不能把多个搜索窗口或非连续片段拼成“证据”。独立复核记录用逐题 `artifact_fingerprint` 绑定当时的公开题面、审计、base/patched IR 和求解结果；任何工件改变后必须重新复核。

Rapid-v0 保留的硬门包括：来源权威且当前可访问、支持段落真实直接、规则适用、题面本地事实足以推出补丁、补丁不是纯数值填空、base 和 patched 均最优可解、两者可接受最优行动集合不相交、题面不泄露规则结论。

来源复查收据绑定当前 audit 的 URL、候选来源、文档、规则原子和支持段落哈希；目录元数据与题目不一致或网页跳转到未批准官方域名时不能晋级。base 中全部非固定变量必须进入行动投影，最优目标的枚举比较使用十进制精确次序；模型拒绝小于 `1e-6` 的非零系数或 RHS，避免数值容差把次优行动误记为并列最优。

题面最后只说明必须遵守哪一类现行规则。外部规则中的天数、小时、比例、门槛以及“至少、至多、不得、方可”等结论不得写进合规句；候选行动自身的日期、时点、容量和业务属性仍须作为本地事实保留，让答题系统通过搜索判断哪些候选可行。

本轨道不要求双网页路径、24/72 小时连续探测、双求解器、复杂身份认证或发布级哈希链。这些门只留给严格正式版；Rapid-v0 的降级不允许牺牲规则真实性、适用性、结构影响和答案变化。
