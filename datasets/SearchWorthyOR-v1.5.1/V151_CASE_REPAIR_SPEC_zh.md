# SearchWorthyOR V1.5.1 题目修复规范（执行版）

## 0. 文档性质

本文是普通 Markdown 工作规范，用于指导 SearchWorthyOR V1.4.4 的逐题审计与 V1.5.1 的生成。本文不是已注册的 Codex Skill，不放入 Skill 目录，也不改变当前工具配置。

V1.4.4 是只读输入基线。修复结果写入新的 `SearchWorthyOR-v1.5.1` 目录，不在原目录内覆盖发布数据。

## 1. 唯一目标

将 120 个 source task 的 240 个 C1/C2 case 修复为“需要 Agent 根据题面中的客观事实，自主判断是否搜索，并根据外部权威证据判断是否修改优化模型”的数据集。

每对 case 只保留两个状态：

| 状态 | 含义 | Gold 行为 |
|---|---|---|
| `RETAIN` | 搜索得到的规则对当前 case 的优化模型不产生修改作用 | 保留 Base IR 和基础解 |
| `PATCH_CHANGES` | 搜索得到的规则适用于当前 case，并使模型修改后的最优决策发生变化 | 应用 typed Patch、重求解并得到不同决策 |

本版本不建立 `PATCH_STABLE` 状态。

## 3. 数据单元与文件职责

### 3.1 `public/tasks_zh.jsonl`

共 120 行，每行是一个 source task。主要字段为：

- `id`：如 `SWOR-R001`；
- `problem_zh`：C1/C2 共用的优化背景、候选行动、数值和目标；
- `output_schema`：公开 action ID、行动含义和目标单位。

这里不应写入仅属于 C1 或 C2 的对象属性，也不应直接写入法规适用结论。

### 3.2 `public/applicability_cases_zh.jsonl`

共 240 行。每个 source task 必须有一条 C1 和一条 C2。字段保持为：

```text
case_facts, case_id, output_schema, pair_id, problem_zh,
source_task_id, prompt_zh, base_semantics_contract
```

其中：

- `case_facts` 保存 `decision_date`、`jurisdiction`、`regulated_subject`、`boundary_facts`；
- `problem_zh` 是 case facts、基础语义合同、解释优先级和共通优化骨架拼接后的题目；
- `prompt_zh` 是 `problem_zh` 再拼接公开 `output_schema` 后的完整模型输入；
- `prompt_zh` 是公开评测时唯一的任务正文。

### 3.3 IR 是什么

IR 是 Intermediate Representation，即优化模型的机器可读中间表示。它明确记录变量、变量类型、目标函数、约束和系数。Base IR 表示只根据题面建立的基础模型；patched IR 表示证据被准入并应用 Patch 后的模型。

IR、Gold Patch 和求解结果属于私有评测/验证材料，不进入公开题面。

## 4. 哪些题目必须修

逐题检查以下七类问题。命中任意一类即进入修复清单。

| 类型 | 问题表现 | 修复目标 |
|---|---|---|
| L1 适用性结论泄露 | 直接说商品属于范围、主体受规则约束、case 获得豁免、某分支被触发 | 改为八位商品编码、主体身份、地点、日期、数量等原始事实 |
| L2 搜索触发泄露 | 直接要求遵守、查询或核验某项现行规则 | 删除该提示，让 Agent 自主识别外部知识缺口 |
| L3 元任务语言 | 告诉模型题面省略了什么、需要自行判断什么、两个 case 区别在哪里 | 删除出题者旁白，只保留真实业务叙述 |
| L4 事实粒度不足 | 只给“大类名称”，无法从官方规则确定范围 | 补充真实世界中用于判定范围的属性，如 CN code、主体类型、有效日期或经营边界 |
| L5 法规—行动映射缺失 | 法规规定义务，但题面没有说明哪个候选行动具备履行能力 | 用业务事实明确行动能力和本地成本，同时不写外部触发条件 |
| L6 Gold 或法规边界错误 | 阈值方向、等号边界、累计主体、日期版本或例外处理错误 | 依据决策日有效的官方原文修正 Patch、IR 和求解结果 |
| L7 共通背景与 case 矛盾 | 共通 `problem_zh` 已写死结论，`case_facts` 又试图覆盖它 | 将差异事实移到 case 层，并消除最终 `prompt_zh` 中的自相矛盾 |

自动关键词扫描只用于发现候选问题，不能替代逐题语义审查。英文同义表达、委婉泄露和行动映射矛盾也必须人工判断。

## 5. 修复时的内容边界

### 5.1 外部证据负责什么

外部权威证据只负责回答：

1. 哪类对象或主体进入规则范围；
2. 规则在什么辖区和日期有效；
3. 数量、状态或行为达到何种条件时产生何种义务；
4. 正式例外和边界如何处理。

### 5.2 题面本地事实负责什么

题面负责给出：

1. 当前 case 的可观察属性；
2. 候选行动、成本、收益、预算和互斥关系；
3. 某候选行动能提供的企业能力；
4. 企业关于可执行方案的业务规则。

例如，法规可以规定超过阈值后需要取得资格、保存记录、提交申报并购买和交回凭证；法规并不规定题目中的行动 `P`，也不规定 `P` 成本为 8 点。题面可以正面说明 `P` 提供这些能力、对应 8 点成本，以及依法需要这些能力的组合须选择 `P`。这样给出了外部义务到内部行动的桥梁，但没有提前告诉模型何时触发义务。

## 6. 单个题对的标准修复流程

### 第 1 步：读取最终输入，而非只看源字段

同时读取 source task、C1、C2、公开 schema、私有 Patch、Base IR、patched IR 和 `solve_result.json`。重点检查两个最终 `prompt_zh`。

### 第 2 步：核对决策日有效的官方证据

优先使用法规正文、监管机构页面、正式标准或行业主管机关文件。记录：

- 来源 URL 与文件名称；
- 适用的主体、辖区、日期和对象；
- 运算符、阈值、单位和等号边界；
- 例外；
- 可直接支持哪个 Patch slot。

### 第 3 步：确定两个 case 的真实差异轴

优先只改变一个边界维度，例如商品编码、主体资格、辖区、日期或规模。其余优化结构保持相同。C1 的事实应导向 `RETAIN`，C2 的事实应导向 `PATCH_CHANGES`。

### 第 4 步：最小修改共通 `problem_zh`

保留原有业务背景、候选行动、数值、预算、目标、互斥关系和时间。删除共通背景中的适用性结论、搜索指令和 case 专属事实。若行动映射不足，只补一条清晰的本地业务规则。

### 第 5 步：重写 C1/C2 的 `case_facts`

使用可观察事实，不写法律结论。商品范围题应优先写准确编码和商品描述；主体题应写注册类型、业务角色和行为；日期题应写事件和决策日期；辖区题应写具体地点和交易路径。

### 第 6 步：同步公开 `output_schema`

action ID、类型和目标单位原则上保持不变。若 C1/C2 的对象类别不同，行动含义改为不与 case 专属属性冲突的表述，例如“选择批次 A（20 吨）”，具体商品属性由 `case_facts` 给出。

### 第 7 步：按原格式重新渲染

保持以下顺序：

1. `【本 case 权威事实】`；
2. `【基础优化语义合同】`；
3. `【解释优先级】`；
4. `【优化骨架】`；
5. `公开 output_schema`。

不得手工只改 `prompt_zh`。应由 source task 和 case facts 统一生成 `problem_zh` 与 `prompt_zh`，避免三处文本漂移。

### 第 8 步：同步私有 Gold

若语义变化影响模型，必须同步更新：

- applicability Gold；
- evidence-to-Patch 绑定；
- typed Patch；
- `base_ir.json`；
- `patched_ir.json`；
- `solve_result.json`。

只改公开题面而保留旧 Gold 不算完成修复。

### 第 9 步：重新求解和复核

对 Base IR 与 patched IR 重新求解，检查可行解、目标值和最优行动集合。随后逐对阅读最终 C1/C2 `prompt_zh`，确认模型看不到状态结论，同时又拥有完成判断所需的客观事实。

## 7. 最小改动矩阵

| 内容 | 默认处理 | 允许修改的条件 |
|---|---|---|
| `source_task_id`、`case_id`、`pair_id` | 保持 | 当前阶段不改名 |
| 决策日期 | 保持 | 与法规版本或事件事实冲突时修正，并记录原因 |
| 辖区、主体 | 保持 | 现有描述直接泄露结论时，只改造成客观身份事实 |
| action ID 和类型 | 保持 | 仅在结构本身错误且无法兼容时修改 |
| 数量、成本、收益、预算 | 保持 | Gold 边界错误或模型不可表达时修正 |
| 目标结构 | 保持 | 官方后果确实改变目标且有证据支持时修改 |
| 共通背景 | 局部修句 | 删除泄露、搜索提示、矛盾和元说明；补齐必要行动映射 |
| `case_facts` | 局部修句 | 用可观察属性替换法律结论 |
| 公开行动含义 | 保持 | case 专属商品名称造成 C1/C2 冲突时泛化 |
| 私有 Patch/IR/求解结果 | 根据新语义同步 | 任何影响数学模型的改动都必须重算 |

## 8. R001 的完整修复示例

### 8.1 官方边界

决策日为 2026-01-02。欧盟 CBAM 的商品范围由 Regulation (EU) 2023/956 Annex I 的 CN code 决定。Regulation (EU) 2025/2083 Article 2a 与 Annex VII 将单一质量阈值设为每个进口商、每个日历年累计 50 吨净重。

边界必须按“超过 50 吨”处理：累计净重等于 50 吨时仍处于 de minimis 范围；任何严格大于 50 吨的累计量才进入相关义务。官方依据：

- EUR-Lex，Regulation (EU) 2025/2083：<https://eur-lex.europa.eu/eli/reg/2025/2083/oj/eng>
- EUR-Lex，Regulation (EU) 2023/956 consolidated text：<https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A02023R0956-20251020>
- European Commission，CBAM definitive regime：<https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/cbam-definitive-regime_en>

### 8.2 拟修订的共通 `problem_zh`

> 欧盟年度进口组合。2026年1月2日，鹿特丹岚桥贸易公司要为2026年从六个候选批次中恰好选择三个进口。六批货物由同一进口主体报关，批次A至F的净重和商业价值依次为：A为20吨、24点；B为18吨、23点；C为17吨、22点；D为16吨、21点；E为15吨、20点；F为14吨、19点。每个批次的具体商品名称和八位CN编码见本case权威事实。年度进口运营方案P提供监管资格或账户办理、年度记录保存、年度申报以及凭证购买和交回的执行能力。凡依法需要上述能力的进口组合，均须同时选择P。P的固定成本为8个净进口价值点。唯一目标是最大化三个进口批次的商业价值减去运营方案成本。请按output_schema中的action_id返回最优行动，并给出目标值及其单位。

这段共通背景保留原日期、企业、六个批次数量、价值、三选一结构、P 的 8 点成本和目标，仅移除适用性结论及搜索触发提示，并补齐法规义务到行动 P 的本地映射。

### 8.3 拟修订的 C1 `case_facts`

```json
{
  "decision_date": "2026-01-02",
  "jurisdiction": "European Union CBAM customs territory",
  "regulated_subject": "An EU-established importer planning its 2026 imports",
  "boundary_facts": "批次A为CN 3105 60 00的磷钾肥料，批次B为CN 7202 30 00的硅锰铁，批次C为CN 7202 50 00的硅铬铁，批次D为CN 7202 70 00的钼铁，批次E为CN 7202 80 00的钨铁及硅钨铁，批次F为CN 7204 10 00的铸铁废碎料。该进口主体在2026年的候选组合由上述六个批次构成。"
}
```

这些编码是 Annex I 相应条目中的明确排除编码。公开题面只给商品事实和编码，不给适用性标签。Gold 状态为 `RETAIN`。

### 8.4 拟修订的 C2 `case_facts`

```json
{
  "decision_date": "2026-01-02",
  "jurisdiction": "European Union CBAM customs territory",
  "regulated_subject": "An EU-established importer planning its 2026 imports",
  "boundary_facts": "批次A为CN 2523 10 00的水泥熟料，批次B为CN 2523 21 00的白色硅酸盐水泥，批次C为CN 2523 29 00的其他硅酸盐水泥，批次D为CN 2523 30 00的矾土水泥，批次E为CN 2523 90 00的其他水硬性水泥，批次F为CN 2814 20 00的氨水。该进口主体在2026年的候选组合由上述六个批次构成。"
}
```

这些编码位于 Annex I 范围内。公开题面仍只给事实和编码。Gold 状态为 `PATCH_CHANGES`。

### 8.5 拟修订的公开行动含义

保留 action ID，将商品名移到 case facts：

| action ID | 新 meaning |
|---|---|
| `swor_r001_a01` | 选择20吨批次A |
| `swor_r001_a02` | 选择18吨批次B |
| `swor_r001_a03` | 选择17吨批次C |
| `swor_r001_a04` | 选择16吨批次D |
| `swor_r001_a05` | 选择15吨批次E |
| `swor_r001_a06` | 选择14吨批次F |
| `swor_r001_a07` | 选择年度进口运营方案P |

### 8.6 R001 的数学与答案校正

令 A 至 F 和 P 为二元变量，且 A 至 F 中恰好选择三个。C2 的最小约束可写为：

```text
20A + 18B + 17C + 16D + 15E + 14F <= 50 + 5P
```

解释：P=0 时组合净重至多 50 吨；P=1 时允许覆盖本题三批组合的最大净重 55 吨。现有 V1.4.4 将边界做成 49 吨，错误地把等于 50 吨也视为触发。

| case | 正确状态 | 最优批次 | P | 目标值 |
|---|---|---|---:|---:|
| R001-C1 | `RETAIN` | A+B+C | 0 | 69 |
| R001-C2 | `PATCH_CHANGES` | B+C+E | 0 | 65 |

C2 中，B+C+E 的总净重为 50 吨，价值为 65；A+B+C 的总净重为 55 吨，若选择 P 后净价值为 61。因此外部证据虽然没有使最终方案选择 P，却改变了约束和最优批次组合。这仍属于 `PATCH_CHANGES`。

## 9. 全部 120 题的批量执行方式

不得直接用一组关键词批量替换 120 题。采用“自动初筛 + 逐题修复 + 全量确定性验证”的方式：

1. 从 V1.4.4 复制结构到新的 V1.5.1 工作目录；
2. 为 120 个 source task 建立修复清单，记录 L1 至 L7 命中项；
3. 按法规/标准主题分组，逐题读取决策日有效的官方证据；
4. 每次只修一个 pair，优先改 `case_facts`，必要时最小修改共通 `problem_zh`；
5. 同步生成两个 case 的 `problem_zh` 和 `prompt_zh`；
6. 同步私有 Gold、Patch、IR 与 solve result；
7. 每完成一组即运行结构、泄露、求解和语义检查；
8. 120 对全部完成后再生成 V1.5.1 的 README、修复记录和验证报告。

建议建立一个持久的机器可读修复表，并由 `build_searchworthyor_v151.py` 读取。修复事实不能只存在于最终 JSONL；README 与生成器/修复表必须同时保存全部改动记录，保证重建后仍然成立。

| Patched 求解 | 可行性、最优行动、目标值 |
| 语义复核 | 题面无结论泄露、事实足够、映射成立 |
| 复核人/日期 | 人工复核与 Codex 复核记录 |

## 11. V1.5.1 验收标准

### 11.1 结构验收

- `tasks_zh.jsonl` 恰好 120 行；
- `applicability_cases_zh.jsonl` 恰好 240 行；
- 每个 source task 恰好对应一条 C1 和一条 C2；
- 所有 case 字段完整，`prompt_zh` 可由源字段确定性重建；
- 公开 action ID 与私有映射一致。

### 11.2 题面验收

- C1/C2 共通背景保持一致；
- case 差异位于可观察事实；
- 最终 `prompt_zh` 不直接给出适用性、豁免、分支触发或 Patch 结论；
- 最终 `prompt_zh` 不包含显式搜索指令或出题者元说明；
- 题面包含完成法规范围判断所必需的主体、辖区、日期和对象属性；
- 外部义务与候选行动之间存在清晰的题目本地映射；
- C1/C2 不能仅靠后缀之外的模板结论词直接识别状态。

### 11.3 数学验收

- 120 个 Base IR 与 120 个 patched IR 均可解析并求解；
- 求解器重算的最优行动集合和目标值与 Gold 一致；
- C1 全部为 `RETAIN`；
- C2 全部为 `PATCH_CHANGES`，且 patched 最优决策与 Base 最优决策不同；
- Patch 的运算符、阈值、单位、等号边界和作用对象均能由官方证据支持；
- 公共 action ID 与 IR 变量映射经过语义检查，而非字符串碰巧相等。

### 11.4 人工验收

- 每个 pair 至少完成一次逐题语义复核；
- 每个主题至少选一对做官方原文、题面、Patch、IR 和最终答案的完整链路复核；
- R001 作为阈值等号边界的固定回归样例；
- 发现错误时，同时更新 README 修复记录和生成器/修复表。

## 12. 明确不在本轮做的事项

- 盲 ID 与统一重命名；
- 文件 hash；
- `PATCH_STABLE` 数据；
- 通过反复追问纠正模型输出格式；
- 为格式输出进行微调；
- 为追求题型变化而重写没有问题的背景；
- 在 V1.4.4 发布目录内直接覆盖现有数据。

## 13. 完成定义

只有同时满足“公开题面修复完成、私有 Gold 同步、全部 IR 重求解通过、逐题语义复核完成、V1.5.1 可由生成器重新构建”时，才可宣布 V1.5.1 完成。
